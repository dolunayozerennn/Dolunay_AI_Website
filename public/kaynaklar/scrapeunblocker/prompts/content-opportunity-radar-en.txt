## ScrapeUnblocker data path

ScrapeUnblocker is the only web data provider. Python SDK:

```python
from scrapeunblocker import Client
su = Client(api_key=anahtar, timeout=180.0, max_retries=0)
```

Disable SDK retries; retry/budget/counter control belongs to the product, so the manifest's
attempt count stays accurate.

`main` cannot be a stub. `build_live_transports(api_key, client_cls=None)` must lazily import
`Client`, build it with the arguments above, and return all three adapters as
`{"get_parsed": ..., "serp": ..., "get_page_source": ...}` (callable). The real
`get_parsed()` returns a `ParsedPage(page_type, source, data, raw)` object; normalize it as
`{"status_code":200,"data":{"page_type":obj.page_type,"source":obj.source,"data":obj.data}}`.
Passing the object as-is, or keeping only `obj.data` and losing `page_type`/`source`, is
forbidden. The SDK reports errors by RAISING (the `ScrapeUnblockerError` family, carrying `status_code`), never by returning a dict. ALL THREE adapter bodies must sit inside `try/except` and map the exception onto your policy; a raw SDK exception must never escape an adapter and no traceback may reach the user. `main` follows input -> key -> live
transport -> `run_radar` -> atomic output, no offline early exit. The signature
`main(argv=None, kok=None, client_cls=None)` is mandatory: with `kok` ALL outputs — `runs/`,
`son_kosu.json`, `son_rapor.html`, `.env` — go there; with `client_cls`, transports build from
that class.

The official response is `{data:{page_type,source,data}}`; walk through temporary `data`,
`result`, `parsed_data`, `payload` wrappers. Don't invent fields; reject if core numbers are
missing.

Don't invent `page_type`: live measurement returned only two values — `social_profile` for a
profile, `social_post` for a post/video. There is NO platform-named value like
`instagram_post`; infer the platform from the URL. Any other value is an unrecognized
schema and triggers the raw fallback.

### Instagram is the primary route

Profile: one request per account, `su.get_parsed(f"https://www.instagram.com/{kullanici}/")`.
Fields: `username`, `full_name`, `verified`, `private`, `biography`, `followers`,
`following`, `external_urls`, `avatar_url`, `recent_posts`. `posts_count` mostly comes back
`None`; don't use it.

`recent_posts` carries 12 posts: `shortcode`, `url`, `caption`, `thumbnail_url`,
`media_type`, `product_type`. This list gives post URLs for free; don't use SERP to find
Instagram posts. Its `likes`, `comments`, `counts_hidden` came back `None` in every record; don't expect engagement numbers from
the profile.

Numbers only come from the post URL, one request per post: `su.get_parsed(gonderi_adresi)`.
Fields: `likes`, `comments`, `counts_hidden`, `posted_at`, `posted_timestamp`, `post_id`,
`media_type`, `product_type`, `carousel_count`, `caption`, `thumbnail_url`, `video_url`,
`location`, `hashtags`, `author`.

**A post with `counts_hidden: true` has a FAKE like count**; Instagram puts a small number
like 3 in `likes` when hiding them. This post must NEVER enter the median, average, brief
candidate pool, "winning openings" list, or the on-screen "exact measurement" counter; the
evidence table's like cell should read "hidden," not a number, while the comment count still
shows. Filter on `counts_hidden`, not `None`: a `None`-only filter had let hidden posts leak
through and a low-comment post win a brief (measured).

`author` is a Mapping containing `username`, but this is **not the scanned account**: on a
collab post it's the other author. Tag every post with the scanned account; if `author`
differs, append "(collab with @X)" in the evidence, otherwise the evidence line cites
another account's median (measured).

Instagram has **NO** view, play, share, save or subtitle counter; don't request,
estimate, or zero-fill it. `product_type` takes three values: `clips` (Reels),
`carousel_container`, `feed`. `recent_posts` order is NOT chronological; build order from
`posted_at`.

### TikTok is secondary and optional

If no TikTok account is given, never run this section; write "TikTok not provided" in the
report. If given, run it AFTER Instagram, with the remaining budget.

Don't search video URLs from raw Google HTML; use this method:
`su.serp("site:tiktok.com/@KULLANICI/video", pages_to_check=SAYFA)`. Accept only the pattern
`https://www.tiktok.com/@KULLANICI/video/15-25_HANELI_KIMLIK` anywhere in the response,
require an exact username match, dedupe. `su.serp()` returns a ready-made dict; don't
peel a `data` wrapper from it — `cevap.get("data")` empties the payload. Normalization
applies only to `get_parsed`.

The canonical video URL does NOT return metrics — it returns a 567-byte "Site Maintenance"
page. Get it from the embed instead:
`su.get_page_source(f"https://www.tiktok.com/embed/v2/{kimlik}")`. The numbers live in the
`<script id="__FRONTITY_CONNECT_STATE__" type="application/json">` block, at
`durum["source"]["data"][f"/embed/v2/{kimlik}"]["videoData"]`; this `data` layer is REAL,
don't skip it. Under `itemInfos`: `playCount`, `diggCount`, `commentCount`, `shareCount`,
`createTime`, `text`. `collectCount` and `subtitleInfos` are NOT in the embed response. Since
the HTML is pretty-printed, put `\s*` between `>` and `{` in the regex.

## Failure contract

- `400`, `401`, `402`: no retry, stop the run, give a plain, safe message. These are not
  recoverable: `main` must exit non-zero and must not present the run as successful.
- `403`, `404`, `415`, `422`: no retry, warn for that target, continue with the others.
- The policy function must accept an injected `sleep_fn=time.sleep`, never call `time.sleep`
  directly. On `408`, `429`, `502`, `503`, `504` and network errors, call `sleep_fn` with real
  `1`, `2`, `4` and retry at most three times. Every retry counts against the budget; sleeping
  `0` is forbidden.
- HTTP `200` alone isn't success: don't accept an empty body, a robot check, `recaptcha`,
  `unusual traffic`, `consent.google.com`, or an unrecognized social schema; it still counts
  toward `billable_2xx` as a `2xx`.
- If no post data arrived, don't produce an empty report; don't overwrite the previous good
  run.

## Analysis and report

The screen is built for SCANNING, not reading: bullets/badges over prose, evidence behind
`<details>`, real post covers on the first screen.

Since Instagram has no view count, rank by three MEASURED signals:

1. **In-account jump** = the post's likes / the median of that account's measured posts.
2. **Comment / like ratio** = conversation power.
3. **Like / follower ratio** = size-independent comparison.

A ratio's denominator only includes posts where that counter was measured; if never measured,
the ratio stays `None` and the screen shows `—`, never zero. Show both average and median.

Don't calculate posting cadence from the date range of ALL posts; `recent_posts` isn't
chronological (measured, one stray old post skewed cadence). Measure cadence in a 60-day window back from the newest post and state the post count in
that window.

The report's first viewport holds **Three videos you can shoot right now** — three briefs
from three DIFFERENT pieces of evidence: highest in-account jump, highest comment/like ratio,
highest like/follower ratio.

Every ratio ranking must first pass a VOLUME FLOOR: a post below the candidate pool's own
median can't enter it (no floor in pools under four; if the filter would empty the pool, it
stays as-is); unfloored, a 17-comment post beat 124- and 86-comment posts (measured).

Narrow the candidate pool to the last 12 months; don't narrow it if fewer than three
candidates would remain (measured). In
the evidence sentence, write the age next to the date ("3 months ago", "1 year ago").

The evidence pool is competitor accounts first; if none come from competitors, fall back to
the user's own account. Every brief needs a topic seed,
an opening structure, a shooting decision, exact numeric evidence, and the source post URL.
Don't build causal claims.

Five more rules:

- The **topic seed** can't be a raw caption slice: take the caption's FIRST LINE, strip any
  @-mention and Turkish suffix on it, `#hashtags`, emoji, URLs, and standalone
  punctuation-separator lines. If that line has fewer than two words, fall back to the first
  sentence.
- The **opening structure** must NOT repeat the topic seed. It states what to DO in the first
  three seconds, not what will be shot. Never copy this prompt's examples verbatim.
- **The three briefs may not be copies of each other.** No sentence may appear in two cards;
  swapping the topic name into the same template does NOT count as different. Every item is
  an instruction of at most 25 words (never a paragraph) and states a SEPARATE decision from
  its own evidence; `ADAPT` carries the job sentence once and does not repeat the `HOOK` line.
  The three calls must SEE each other: pass earlier cards' sentences in; regenerate any
  repeat. Measured: the repeat moved from `SHOOT` to `ADAPT` to this prompt's example.
- If the **jump factor is below 1**, don't construct a praise sentence — instead of "0.77x,"
  say "its likes are below its own median." Don't glue a suffix onto the percentage ("0.73%'s
  of its followers"); write it clean: "likes per follower: 0.73%."
- **Bullet splitting** only breaks at a `.`/`!`/`?` + capital-letter boundary; splitting on
  semicolons is FORBIDDEN — in Turkish `;` joins a dependent clause, producing
  lowercase-starting half-bullets (tried, reverted).

After that: what changed this run, data warnings, account panorama, **format comparison**
(median likes and post count for `clips`, `carousel_container`, `feed`), **winning openings**
(best posts' caption first line), posting cadence, the full evidence table, the TikTok
section if present, raw topic signals, and call-to-action reality.

Measure raw topic signals by how many separate POSTS a word appears in, not repeat count;
@-mentions and #hashtags must not enter the word cloud (each stays in its own list). Prefer a
discriminative measure over plain frequency: words appearing only in posts above their own
median, never below it; break ties by summed jump factors across the posts containing the
word, not alphabetically. Keep a filter list for generic filler (pronouns, conjunctions,
"great," "nice," "thanks," call-to-action stock phrases) (measured).

Same input, same report: sorts break ties on a fixed data field (the word itself, for word
count), never dict/set order (`PYTHONHASHSEED`-dependent).

The report is one dark-themed HTML file, readable offline, text/data/covers embedded
(data-URI) — no JS, font CDN, or external request except the fetched-post embed iframe;
cover survives offline, no player. A post with no cover shows a `kapak inmedi`
(cover didn't load) box instead of a bare/empty player. Add this CSP:

```html
default-src 'none'; img-src data:; style-src 'unsafe-inline';
frame-src https://www.instagram.com https://www.tiktok.com;
base-uri 'none'; form-action 'none'
```

The quota text must read exactly: "Signing up grants 500 free requests, one time. It
does not renew monthly." Don't estimate the cost of failed responses; show only `attempts`, `billable_2xx` and
`cache_hits`.
