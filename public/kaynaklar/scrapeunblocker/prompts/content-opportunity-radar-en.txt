Build, test, collect the data and open the report. Leave no terminal work to me.

Ask everything in one message: what I do (one sentence), my TikTok username, one to four
competitor TikTok usernames, optional TikTok-to-Instagram username mappings, and Quick or Deep mode.

Do **not** ask for the API key in chat. Build the files, then launch the app in an
interactive terminal; the app must collect the key with `getpass`. The key must never appear
in an argument, Claude message, log, HTML, JSON or git.

Read the target back before starting: "I will compare @me with @a and @b in Quick mode."
Accept `@username` and profile URLs.

The mandatory data path is `business_context -> run_radar -> data.json -> adapt_brief`.
Call `adapt_brief(business_context, evidence)` for all three briefs. Every `adaptation`
must contain the normalized job sentence verbatim and appear as **Adaptation for your
business**. A fixed `DEFAULT_ADAPTATIONS` list, printing the sentence or only storing it
in JSON is forbidden. With identical evidence, changing the sentence changes all three.

## ScrapeUnblocker data path

ScrapeUnblocker is the only web data provider. Use the official Python SDK:

```python
from scrapeunblocker import Client
su = Client(api_key=key, timeout=180.0, max_retries=0)
```

Disable SDK retries; the product owns retries, budget and counters, so manifest attempt
count stays accurate.

`main` cannot be a stub. `build_live_transports(api_key, client_cls=None)` lazily imports
`Client` when absent, uses the arguments above and returns all three SDK adapters as the
dictionary `{"get_parsed": ..., "serp": ..., "get_page_source": ...}`. Every value must be
directly callable, never a class. `main` must use that dictionary and must not build the
transports twice. Real
`get_parsed()` returns `ParsedPage(page_type, source, data, raw)`: normalize it exactly as
`{"status_code":200,"data":{"page_type":obj.page_type,"source":obj.source,"data":obj.data}}`.
Passing the object through or keeping only `obj.data` loses metadata and is forbidden. Preserve SDK error `status_code`. `main` executes input -> key -> live transports
-> `run_radar` -> atomic output; it has no offline early exit. The signature
`main(argv=None, root=None, client_cls=None)` is mandatory and argv comes first: with
`root`, every output — `runs/`, `latest_run.json`, `latest_report.html`, `.env` — goes under
that folder; with `client_cls`, build the transports from that class. Tests call main this
way in an empty temp folder.

Use `su.get_parsed(url)` first. Preserve TikTok profile `username/followers/following/likes/
videos`; post `video_id/description/plays/likes/comments/shares/saves/reposts/posted_at/
duration_s/cover_url/hashtags/music/author`; Instagram profile `username/followers/
recent_posts`; post `shortcode/caption/likes/comments/posted_at/media_type/counts_hidden`.

The response is normally `{data:{page_type,source,data}}`. Walk temporary `data`, `result`,
`parsed_data` and `payload` wrappers. Never invent fields. Reject absent core metrics.

Never invent `page_type`. A live measurement on 14 August 2026 returned only two values:
`social_profile` for profiles (TikTok and Instagram alike) and `social_post` for posts and
videos. Platform-flavoured values such as `tiktok_video` DO NOT exist; a validator that
expects them rejects every live response. Tell the platforms apart from the URL. Anything
else is an unrecognised schema and triggers the controlled raw fallback.

Do not parse raw Google HTML for TikTok URLs. Use the official SERP method:

```python
su.serp("site:tiktok.com/@USERNAME/video", pages_to_check=PAGES)
```

Accept only exact URLs matching
`https://www.tiktok.com/@USERNAME/video/15_TO_25_DIGIT_ID`. Require the exact username and
deduplicate.

Raw HTML is not a primary source. Use `get_page_source` only to add a missing transcript or
cover to top videos, or for a controlled TikTok fallback when parsed data has an unknown
shape. Record fallback in the manifest/report and read only the
`__UNIVERSAL_DATA_FOR_REHYDRATION__` JSON. In ASR/VTT the first three seconds are the opening;
mark late speech. Download parsed cover URLs only for top videos, cap at 180 KB and embed as `data:` URIs.

## Two modes and hard budgets

Hard-code these modes:

| Mode | Videos/account | SERP pages | Raw enrich/account | Instagram posts | Attempt budget |
|---|---:|---:|---:|---:|---:|
| Quick | 6 | 1 | 2 | 2 | 56 |
| Deep | 20 | 2 | 4 | 5 | 160 |

Every SDK attempt consumes budget; cache hits do not. A retry is another attempt. Keep
partial data at the limit. Process accounts round-robin. Concurrency is `1`.

Cache every parsed, raw and SERP response under a hash of URL plus request type. Cache is
valid six hours. `--yenile` bypasses it. Cache files must never contain the key.

## Failure contract

- `400`, `401`, `402`: no retry. Stop immediately with a safe plain-language message.
- `403`, `404`, `415`, `422`: no retry. Warn for that target and continue other accounts.
- The policy function accepts injected `sleep_fn=time.sleep` and never calls `time.sleep`
  directly. For `408`, `429`, `502`, `503`, `504`, and network errors, call `sleep_fn` with
  real `1`, `2`, `4`, retry at most three times, and charge every retry. Sleeping `0` fails.
- HTTP `200` alone is not success. Reject empty content, robot checks, `recaptcha`,
  `unusual traffic`, `consent.google.com`, or an unknown social schema. It is still a `2xx`,
  so increment `billable_2xx`.
- If no exact video metrics arrive, do not create an empty report. Preserve the previous
  good run.

## Key security

Use the environment or local `.env` when present, otherwise hidden `getpass` input.
Regardless of its source, keep the exact key in the same variable until the first SDK `2xx`
response. At that moment, use one path such as `persist_key_once(key)` to write `.env`
**exactly once** and set mode `0600`; later `2xx` responses must not write again. A run with
`400/401/402` or no `2xx` must not create `.env`; never save an invalid key. Clear
the in-memory key only after this persistence decision. Do not implement `--anahtar` or
`--key`. Do not log exception bodies.
